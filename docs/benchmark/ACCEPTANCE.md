# Build stages and completion gates

Show a concise whole-build plan then proceed. The stage table is a suggested route; reorder, combine or replace methods when a better approach meets all gates and outcomes. The benchmark prompt authorises sensible evidence-led choices; routine intermediate approval is not needed for this local benchmark. Real sources, paid services and protected image-generation approval gates remain binding.

| Stage | Inputs → output | Gate |
|---|---|---|
| 0: Freeze/preflight | Clean release + original input allowlist + tool inventory → own run, source hashes, scope, unknowns and PLAN | No sealed input read; actual file/tool availability; no prior budget inherited. |
| 1: Survey/spec | Drawings/photos/video/scans/terrain → independently measured structures, rooms, ground, openings, finishes and complete item inventory | Drawn-back plans/elevations, scale/level/revision checks; unknowns explicit. No generated old spec copied. |
| 2: Build/kit | Independent data + shared tools/eligible assets → editable Before/After, full room furnishing, reusable catalogue/thumbnails and site | Exact dimensions/contact, finished faces, coherent detail, complete room inventory; integrity before finish/spec/export. |
| 3: Product | Shared product systems adapted to own site → working planner, all editors, VR/input/help, persistent shared design | R08–R22 exercised end-to-end on actual saved/exported build; recoverability and preservation. |
| 4: Look/speed | Own model → readable daylight/golden hour/night and smooth navigation | Match original renders/cameras; no pop/freeze/overlap; viewport sizes and XR simulator measured, physical status distinct. |
| 5: Presentation | Actual house → native three-space stills, tour rehearsal, editable premium pipeline | Inspect frames and motion. Paid/AI output only with approvals; exact limitations named. |
| 6: Freeze/present | Tested full product → submission hashes, local links, screenshots, source and report | Every requirement has pass/pending/blocked evidence. Present before opening any prior result. |

A required feature cannot be dropped by moving it to a future stage. Carry forward unresolved work and finish it; externally blocked gates stay blocked, not passed. A presentation of an incomplete checkpoint does not make it a completed benchmark entry. Comparison unlock is for the frozen, honestly labelled final submission presented to Jack, not a plan/progress update.

## Practical evidence, not a giant ledger
- Unit tests for geometry, snapping, transforms, independent height, history, shared saves/conflicts and host contacts. Test actual troublesome bowl/lamp behavior and boundary joins, not code mirrored back to itself.
- Browser walkthrough covering every room and outside, Before/After and furnishings; doors, stairs, narrow passages, room destinations and garden→house, with editor minimised and restored.
- Desktop/phone/iPad and simulated Quest controls including left/right handed roles; real device acceptance remains separate. Cold load and reconnect; hover/selection visuals off for evidence.
- Fixed kitchen-diner, lounge and front-left garden camera/lens/light comparisons; each room inspected and flagged close-ups. Avoid thousands of redundant captures after a relevant check already passes.
- Validate actual served model hashes, data, materials/textures and compressed twins after publication to own isolated site. No promoting to Jack's live site as part of a benchmark.
- Use all lesson families from both logs: record source document + row/ID, applicability, preventive implementation and actual check. New failures are logged before fixes, and closure includes observed evidence.

## Submission files
`PLAN.md`, `PROGRESS.md`, `SOURCE-REGISTER.json`, `LESSON-COVERAGE.md`, `ACCEPTANCE.md`, `TOOL-PREFLIGHT.md`, editable master(s), shared layout/spec, assets/licenses/thumbnails, rebuild/start instructions, original screenshots + tour, performance report, `SUBMISSION.json` with source/build/evidence hashes and time, and `PRESENTED.md` with the actual presentation time/link/message. Do not manufacture usage/time data. Record model/provider/version where observable and unknown where not.

Before opening comparison material, first deliver the independent result and freeze it. Afterwards preserve it unchanged and make an explicitly comparison-assisted branch. Technical checks plus own visual inspection are essential; no benchmark can certify planning compliance, survey accuracy or physical-device performance without that evidence.
