## What to build
1. **The studio furniture kit** (`tools/library/kit/`): bring in your furnishing generator and its catalogue as our own,
   parameterised by size and style, for every client house. One axis convention for everything (X width, Y depth, Z up, front
   -Y, bottom-centred, metres). Built to exact sizes; never stretch a whole item. Real-metre UVs, one reviewed CC0 material set,
   support/seating built in (fruit in bowls, throws on sofas, towels on rails). Keep every licence and source recorded.
2. **A broader catalogue in styles:** at least modern, contemporary, Scandinavian, country/farmhouse, industrial and
   traditional, each a coherent set (materials, proportions, details) across the kinds that matter: sofas, armchairs, tables,
   chairs, beds, bedside tables, wardrobes, dressers, rugs, curtains/blinds, lamps (table, floor, pendant), mirrors, art, plants,
   cushions/throws, kitchen and bathroom fittings, appliances. Quality bar: the interior you built for Battle Road, close up.
3. **Thumbnails:** a small picture of every catalogue item (about 256 px, front three-quarter view, neutral studio light),
   generated by script (headless Blender with Eevee or Workbench, or three.js offscreen), one at a time, stored beside the
   catalogue. Regenerate automatically when an item changes.
4. **Furniture placed at runtime, not baked:** each catalogue item exports as its own small model (instanced where repeated).
   A layout file per site and version (e.g. `assets/sites/<site>/layout/<version>.json`: item id, catalogue kind/style/variant,
   position, rotation, host surface, room) is what the viewer loads. Start the layout for Battle Road from the signed spec's
   items, so today's furniture keeps its places, and switch the house build so its baked loose furniture is replaced by the
   layout (fixed fittings stay in the house model).
5. **Furnish it yourself in the viewer:** an Edit mode on desktop, phone and in the Quest headset.
   - A catalogue panel with the thumbnails, filtered by room type, kind and style (in the headset, on the wrist panel).
   - Add an item where you point; drag it along the floor (or wall for wall items) with the mouse, touch or the controller
     ray; rotate with Q/E, two fingers or the thumbstick; delete; undo/redo.
   - Snap to walls, corners and other items; live checks while moving: no overlap with walls or furniture, base on its host
     surface, front facing into the room, doors still able to open, a clear walking route kept. A blocked spot shows red and
     won't drop.
6. **Bird's-eye room view:** pick a room and see it from straight above (its plan, with the furniture), and lay it out by
   drag, rotate, add and delete with the same catalogue and checks. Switching back to walking shows exactly the same layout.
   Make the room planner (`planner.html`) read and write the same layout file, so all three views stay in step.
7. **Saving:** a small endpoint in `tools/https-serve.py` (e.g. `GET/POST /layout?site=&version=`) that validates and writes
   the layout file, keeps the previous copy, and logs each change for the next build to bake in. The server running on 8443 is
   Claude's: don't restart or stop it; test with your own server on port 8450.
