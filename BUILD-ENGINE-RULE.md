# Standing rule: build each element in the best tool

Jack · 4 November 2026 · Applies to every architectural, landscape and 3D studio build, and every agent working on it.

**If an element will be better built in Unreal, build it directly in Unreal. Blender is not a required first step.** Decide before authoring; do not build a weaker Blender version merely because the existing pipeline starts there, then pay to rebuild it in Unreal.

This applies to literally any part of the project: shell and structure, roofing, windows, doors, paving, gravel, grass, trees, hedges, planting, furniture, fittings, flooring, walls and interior finishes, materials, weathering, lighting, reflections, animation and effects. These are examples, not limits. Use Blender or another tool where it is actually the better authoring tool for that element. Judge quality, editability, available native systems, measured accuracy and the intended deliverables together.

Before building each element or coherent group, record a concise tool choice and reason in the build plan. Reuse proven assets and systems in the selected tool. Preserve measured dimensions, coordinates and shared layout identities; back up existing work before replacing it and remove or hide superseded geometry so both versions do not overlap. A browser/Quest fallback may be simplified or derived; it must not dictate the quality ceiling of the Unreal presentation.

## Mandatory disclosure of anything missing

**Every preview, stage report and agent handoff must explicitly identify anything absent, simplified or temporary because its proper version is being built in Unreal.** Never say only “the Unreal version will be better.” For each omission or placeholder, state:

- **What is missing or temporary, and where:** name the actual element, finish or effect and the affected view/deliverable.
- **Why Unreal is the better place to build it:** the concrete native capability or quality benefit, not a generic promise.
- **What will replace or complete it:** the intended Unreal implementation.
- **Its actual status:** planned, in progress, built but unverified, or built and visually verified. Identify where the verified result can be seen when available.

If nothing is deferred to Unreal, say so. Do not present a deliberately incomplete Blender/browser preview as the finished scene, or describe an Unreal improvement as completed before inspecting it in Unreal. Clearly separate the measured/shared model, the current preview and the final presentation output.

## Every-agent application

Read this rule at build start and when choosing tools for a new stage. Reference it in all builder/reviewer handoffs, including work delegated to other agents. Check the omission disclosures before showing a preview or reporting completion. Routine tool selection is already authorised by this standing rule; existing spending, licence, privacy and publication constraints still apply.
