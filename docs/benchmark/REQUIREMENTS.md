# Complete product contract

**Method freedom:** paths, engines, endpoint names, schemas and stage order describe the existing baseline, not mandatory technology. An equivalent or better implementation is allowed if it preserves all user-facing capabilities, migration/interchange and checks. Any new format must keep shared edits exact across its views/devices. The matrix specifies outcomes, not how to code them.

Every ID needs an implementation path and current evidence in the run's acceptance table. Existing shared tools are a starting point, not proof of success on a new property. “Required” means part of the finished benchmark product; paid presentation and research-only items have explicit scopes below.

## Research direction retained without pretending it already works
RoomPlan/LiDAR/spatial photos → structured survey → automated editable construction and hundreds of library objects; retain metric provenance/control points for later measured drawings. Existing original USDZ/scans are usable inputs; a custom iPhone app is not required by this benchmark. Automated RoomPlan importer and precise council package require their own validation. Plan-to-3D north star: editable straight/curved architectural walls with dimensions, thickness/height/alignment, grid/angle snapping, tracing image, multi-storey editing, roofs/stairs and vector drawing export. Keep it on the roadmap and expose existing functionality; do not relabel missing architectural CAD as already implemented garden CAD. Premium PCVR streaming, DLSS/Mirage experiments and subscription video tools are capability-dependent research, not assumed installed services.
