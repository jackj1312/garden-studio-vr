# A separate server and click-to-start launcher for every run

Jack, 6 November 2026: every benchmark has its own server, even when the same model is tested again. The launchers have their own Desktop folder: **`~/Desktop/Garden Studio Launchers`**. This owner-only folder is separate from the clean benchmark input. Contestants must not execute earlier run launchers before presenting their own submission.

A new run MUST have a unique output/project folder, dedicated port, saved server command/configuration and double-clickable `.command` launcher. Name it `<exact model> — <YYYY-MM-DD> — Run <number>.command`; always include the date, and add time or a different run number for same-day repeats. Never overwrite a previous run or silently reuse its port. Record provider/model/version from session metadata; if mixed, list contributors. Do not invent a model name from a user's example.

The command starts that run's server if stopped, reuses it if already running, waits until the actual viewer is ready, and opens that run's URL. If the port belongs to another root/application, stop with a clear message; never kill/restart it. Keep logs, a readable configuration (root, model, date, run ID, port, start arguments, URL) and dependency instructions. It must work after closing the agent chat and after a Mac restart. Test cold start, second click and wrong-port ownership safely. A launcher is part of completion, not an optional handoff task.

Use/adapt `tools/benchmark/register_launcher.py` and `launch_server.py` from the active studio checkout, or an equivalent reliable implementation. The publisher carries them under `shared-tools/tools/benchmark/`. Register only when the independent run's own server and URL exist. Results stay in that run's folder; the launcher folder contains commands/config/logs only, never credentials or private source copies.

The two initial legacy launchers point to the existing Codex (GPT 6 Astra, port 8450) and Claude (Opus 5.5, port 8443) live projects. They are identified as legacy/live, not frozen independent benchmark submissions. Claude's recorded project also used Fable 5.1 during planning; the configuration records that provenance. The date is launcher registration, not a claim the whole model was built that day. Each future completed benchmark gets its own separate entry. No extra Fable server is invented for a session that shares the same project/server.
